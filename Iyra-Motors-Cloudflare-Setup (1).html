IYRA MOTORS · CLOUDFLARE PAGES

Install your website and admin dashboard

Use Iyra-Motors-Cloudflare-Pages.zip with Cloudflare Pages direct upload. It contains the compiled website, its images, and its admin server. You do not need to install Node.js or run a build.

Start here

The ZIP is an upload package for Pages. The setup guide you previously received was not a deployable website. The WordPress theme ZIP is also a different product and cannot run as this Cloudflare application.

You need a Cloudflare account with Pages, D1, R2 and Zero Trust Access available; a domain managed through Cloudflare for the protected admin login; and the email address that should manage your dealership.

Complete the account settings below before the full ZIP upload. The website intentionally shows setup guidance until the database, photo bucket and Access configuration are ready. Cloudflare may ask you to activate a service or choose a plan in your own account.

This is a custom React/Vinext website, with Cloudflare handling hosting, storage and login. It does not use WordPress or Dealer Inspire's proprietary software. This export starts with an empty dealership database; existing preview data is not copied automatically.

Step 1

Open or create a Pages project

If you already have a Pages direct-upload project, open it and continue to Step 2.

  1. In Cloudflare, open Workers & Pages → Create application, then choose the Pages option and Drag and drop / Upload assets.
  2. For a new project, first extract the ZIP on your computer. Upload only the index.html file to create a temporary setup page. Name the project, then deploy it.
  3. Open the new Pages project. You can now configure its runtime and resources before uploading the full site.

Keep the original ZIP for Step 7. If your existing Pages project is connected to Git and does not offer a dashboard upload button, create a separate direct-upload Pages project for this package. Cloudflare direct-upload documentation.

Step 3

Create the database and photo bucket

  1. Open Cloudflare's D1 SQL database section. Create a database named iyra-motors-inventory.
  2. Open that database's Console. Expand the SQL below, copy it into the console and select Execute. It creates five tables and their indexes.
  3. Open R2 Object Storage. Create a bucket named iyra-motors-photos. Keep public access disabled; the website serves published vehicle photos through its server.
  4. Return to your Pages project → Settings → Bindings → Add. Add both bindings below.
Binding typeVariable name — exactSelect this resource
D1 databaseDBiyra-motors-inventory

If you already created resources for this same application, you may select those resources instead. Keep their existing data. The SQL below creates missing objects and does not drop tables; it is the initial schema, not a migration for an unrelated application.

Step 4

Attach the dealership domain

In Pages project → Custom domains, add the domain or subdomain customers will use. Follow Cloudflare's DNS instructions and wait for it to show active. Use a domain in a Cloudflare DNS zone for the Access application in the next step.

Choose one exact address, such as https://www.your-dealership-domain.com. That example is a placeholder. Use your own active domain everywhere below. Cloudflare custom-domain instructions.

Step 5

Configure the admin email login

  1. Open Zero Trust in Cloudflare and finish team setup if this is your first time. Note your team domain, in the form https://YOUR-TEAM.cloudflareaccess.com.
  2. For email login codes, open Integrations → Identity providers → Add new identity provider → One-time PIN. You may use an existing identity provider instead.
  3. Under Access controls → Applications, add one Self-hosted public application named Iyra Motors Admin.
  4. Use your active dealership hostname and cover the four paths listed below within this same application. The public homepage should remain outside the protected paths.
  5. Add an Allow policy whose Include → Emails rule contains your administrator email address. Add any other approved staff explicitly. Choose your login method and save.
  6. Copy this application's Application Audience (AUD) Tag, a 64-character value, for Step 6.
HostnamePath
Your dealership hostname/admin
The same hostname/admin/*
The same hostname/api/admin
The same hostname/api/admin/*

The base paths and descendants must be covered. Keep these paths in one Access application with one AUD tag. Leave /, /api/inquiries and /media/* outside Access; the server separately protects draft photos. Do not add an Everyone or Bypass policy to the admin application.

Step 6

Add the website settings

In your Pages project → Settings → Variables and Secrets, add these values to Production. Enter plain values, without surrounding quote marks. The variable names are case-sensitive.

NameValue
AUTH_MODEaccess
ADMIN_EMAILSYour approved admin email. For multiple staff, separate their email addresses with commas.
ACCESS_TEAM_DOMAINYour full https://YOUR-TEAM.cloudflareaccess.com team URL, without a trailing slash.
ACCESS_AUDThe Access application's 64-character AUD tag.
PUBLIC_ORIGINYour exact active HTTPS dealership address, with no path or trailing slash.
RATE_LIMIT_SECRETA random secret, generated below or in your password manager. Store this using Cloudflare's Secret / Encrypt option.

RATE_LIMIT_SECRET supports contact-form rate limiting. It is separate from your login. This guide can generate it locally in your browser; it makes no network requests.

Save the value in Cloudflare and your password manager. Do not send it in chat. You do not need an administrator password in the website code.

Step 7

Upload the complete ZIP

  1. Open your Pages project → Create a new deployment and choose Production.
  2. Upload the original Iyra-Motors-Cloudflare-Pages.zip. The upload root must contain _worker.js, _routes.json, index.html, images/ and _next/. There must not be an extra enclosing folder.
  3. Select Deploy. No build command or framework preset is needed for this compiled direct-upload package.
  4. Open your custom domain. If a setup screen remains, complete the specific missing setting it identifies, then upload the same ZIP as a new production deployment.

Cloudflare supports an advanced-mode _worker.js file inside a Pages dashboard upload. It runs the admin and database logic while Pages serves the images and scripts. Direct upload support · Advanced-mode server format.

Check the website once

  • Open your dealership domain and confirm the homepage and images load.
  • Open https://YOUR-DOMAIN/admin, enter the approved email and complete the Access login.
  • Create a draft car, save it and upload a photo. An incognito visitor should not see the draft.
  • Publish the car and refresh the public website. Confirm it appears.
  • Submit a test contact request and find it in the admin inbox.
  • Update your real business contact details and opening hours in the dashboard. Review demonstration vehicle content before advertising the site.

Inventory, photos and dealership information are saved in D1/R2. Normal admin edits do not require another ZIP upload. This package was tested locally in Cloudflare's Workers runtime, including signed admin authentication, inventory publishing, image storage and inquiries. If something does not work

What you seeWhat to check
An import error mentioning node:Save the compatibility date and nodejs_compat flag in the production Pages runtime, then create a new deployment.
Only the temporary setup pageUpload the full ZIP to the Pages project and open the root URL, without /index.html. Confirm _worker.js is at the upload root.
“Your website files are installed”The server started. Complete the named bindings or variables, initialize D1 if requested, and redeploy.
No upload buttonCheck that this is a Pages direct-upload project. A Git-connected Pages project uses a different deployment workflow.
No email login screen at /adminUse the custom hostname configured in Access. Check all four protected paths and your Access application policy.
Login succeeds but admin access is deniedMatch the email in ADMIN_EMAILS to the signed-in identity. Confirm ACCESS_TEAM_DOMAIN and ACCESS_AUD belong to that same application; then redeploy.
Changes cannot be saved / origin rejectedOpen the exact domain in PUBLIC_ORIGIN. If you switch domains, update that variable, the Pages domain and Access hostnames.
Deployment or runtime error persistsKeep the exact error text from the deployment log and the failed deployment URL. Share those details for diagnosis, without secrets or login codes.
